# White paper citation and build audit record

Status: approved review record
Date: 2026-05-18
Package: `artifacts/dsr-framework-white-paper/`

## Findings

1. The prior PDF rendered the author line as `true` rather than the author name. The safe fix is to use scalar author metadata in both the manuscript YAML and Pandoc metadata file.
2. The prior PDF double-numbered headings because the Markdown headings were manually numbered while Pandoc/LaTeX section numbering was enabled.
3. The prior PDF listed the document title as section 1 because the body repeated the title as an H1 after YAML metadata.
4. The prior reference list was manually numbered and not connected to Pandoc citeproc. The release-quality fix is to use citation keys in the manuscript, a BibTeX file, `--citeproc`, and a cited-only `References` section.
5. The full parsed DSR source bibliography should be retained as a source-registry appendix or supplemental file, not as the main references list.
6. Long prose-like fenced code blocks can run off PDF pages. The layout-safe fix is to keep prose and platform architectures in wrapping Markdown structures, reserve fenced blocks for short literal code, and fail the build check on overlong fenced lines.
7. Pandoc/LaTeX table output needed row-level visual separation for human legibility. The PDF build now inserts row rules into generated longtable bodies and checks the PDF build log for overfull boxes.

## Acceptance criteria

- PDF title page shows `David Ochabski`, not `true`.
- TOC does not show a body section that repeats the title.
- TOC does not show headings like `3 1. Introduction`.
- Main DSR theory claims include author-date citations.
- Main references are generated by Pandoc citeproc from `whitepaper/references.bib`.
- Full parsed source bibliography is retained outside the main references section.
- Long display content wraps within the PDF page instead of running past the margin.
- PDF tables show visible row separation.
- The build check fails on overlong fenced-code lines and overfull hbox warnings.
- No L5 archival/publication-ready claim is introduced.
