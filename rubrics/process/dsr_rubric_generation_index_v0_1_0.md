## How to use this index

1. Choose one rubric from the table. Do not generate all rubrics in a single pass.
2. Open `dsr_rubric_generation_prompts_v0_1_0.txt` and copy the matching prompt ID.
3. Generate a complete YAML rubric artifact for the listed output path.
4. Review the generated rubric against `dsr_rubric_generation_spec_v0_1_0.yaml`.
5. Add source anchors, concept crosswalks, examples, validation implications, and human-review flags before treating the rubric as repository-ready.

## Priority interpretation

| Priority | Meaning |
|---|---|
| core | Needed for a minimally reviewable DSR record or for high-value upstream assessment. |
| recommended | Strongly useful for quality, reuse, or claim discipline, but can follow the core rubrics. |
| advanced | Useful for repository packaging, validation, automation, or cumulative science after core assessment rubrics exist. |

## Dependency logic

- Start with problem-selection rubrics before requirements, artifact, and evaluation rubrics.
- Generate `evaluation_alignment_quality_rubric` before finalizing `contribution_quality_rubric`, because contribution claims should not outrun evaluation evidence.
- Generate `transparency_trace_quality_rubric` before repository packaging or replication-readiness work.
- Treat `responsible_design_constraints_rubric` as cross-cutting; it can be generated earlier if ethics, privacy, security, or stakeholder burden is central to a project.
